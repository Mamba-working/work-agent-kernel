# 持续推进路线图

## 北极星场景

别人正常在群里 @我、私聊我或评论文档，我的 Agent 自动发现并关联工作，使用可替换的 Harness 推进；只有可用结果或需要我的决定才进入统一收件箱。我可以主动提出新任务，也可以随时打开执行 Session 查看。

## P0：架构原型（本次）

- [x] TypeScript 领域模型、四类插件接口、版本化工作流 profile。
- [x] SQLite 事件与事项状态、游标、订阅、Run、Attention、Outbox。
- [x] 可替换测试 Harness、外部 ESM 插件示例、CLI 演示。
- [x] 行为测试、类型反例、Linux/macOS CI 定义。
- [x] DeepSeek 对照、原型限制及真实接入验收定义。

## P1：输入来源与 Router 的真实验证

交付个人飞书来源插件和独立模型 Router 适配器。先只读、只准备草稿。将客户端通知作为可选来源，不假设数据库已解密或桥接接口已可用。收集带来源证据的回放集，验证漏检和错误关联。

退出条件：群 @、私聊、文档评论、主动输入中的同一工作能正确关联；不能覆盖的通知类型明确列出。

## P2：真实 Harness 接入

先实现 Codex App Server，再选一种确实不同的 Harness 做合同验证。建立 provider 接单记录、原生 Session/turn 映射、异常对账和能力说明。明确 Desktop 显示与接管方式。

退出条件：同一事项跨多轮、内核重启仍能继续；丢 ACK 不重复执行；第二种 Harness 通过同一测试集。

## P3：通知与人工决定

实现应用收件箱或飞书卡片 Sink，具备真实回调认证与幂等投递。统一展示事项、建议、依据、选项及 Session 链接。人作出决定后原事项继续。

退出条件：从实际通知点击到实际 Harness 后续执行跑通，重复回调无重复运行。

## P4：工作知识与结果验收

引入适当的持久上下文插件，优先评估 OpenViking；原文、任务状态、个人决定保持清晰拥有权。按报告、文档、代码等结果类型接入验收机制。

退出条件：跨 Session 准确召回适用的决定；产物有证据和实际核实结果。

## P5：有证据再增加运行设施

根据实际故障与使用量，选择任务取消、steering、客户端独占队列、Watchdog、规范化数据库、多设备或 Temporal。避免一次性建立完整云中台。

每个阶段要记录输入、产物、测试、未验证边界。仓库不会自行执行这些阶段，创建 roadmap 不等于已经部署持续自治 Agent。
